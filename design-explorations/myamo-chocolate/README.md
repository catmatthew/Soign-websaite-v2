1. 投稿の検索・絞り込みが使いやすいこと
2. Instagramアカウントへの導線が分かりやすく、流入が増えること

### 試していただきたい操作

1. 検索欄に `Paris` と打つ（2件に絞られます。英字と和文のどちらでも一致します）
2. 国で「フランス」を押す（都市の段が現れ、他の選択肢の件数が変わります）
3. 種類の「パティスリー」が 0 件で押せなくなっていることを確認する
4. 「すべて解除」で元に戻す
5. 案B-2は検索欄を押して専用画面を開く（デスクトップでは `/` キーでも開きます）
6. 案B-1は携帯幅で「絞り込み」ボタンからシートを開く

### ①について：「投稿」の範囲の解釈

ご指示の「投稿の検索」を、**店と投稿の両方を一つの索引として扱う**と解釈しました。
`contents.md` は Shop（店・ブランド）と Post（投稿）を別の型として定義していますが、
探す人はその区別を意識しないためです。3案とも「種別」で店と投稿を切り替えられます。
店だけを索引にする想定であれば、種別の絞り込みを外すだけで対応できます。

現在のサンプルは店10件・投稿6件の計16件です。

### ②について：`design.md` との緊張関係

`design.md` は次の2点を明示的に指示しています。

- 「Instagramはサイトを視覚的に圧迫せずに、複数の自然な場所から辿れること」
- 「Linktreeのようなリンク集に見えないこと」

②の「流入を増やす」を強めるほど、この2点から離れます。
3案はこの軸の**強・中・弱**を意図的に作り分けたものです。
B-3が最も流入に寄り、`design.md` の線に最も近づきます。
どこまで寄せるかがご判断いただきたい点です。

### ②の効果測定について

「流入を増やす」は測らなければ改善できません。本開発フェーズでは次を推奨します。

- Instagramへの外部リンクすべてに UTM パラメータを付け、設置箇所を識別できるようにする
  （例：`?utm_source=site&utm_medium=referral&utm_content=header` / `hero_band` / `card` / `dock`）
- クリックをイベントとして計測し、設置箇所ごとの寄与を比較する
- 設置箇所ごとの効果が分かれば、効いていない箇所を外して `design.md` の指示に戻せます

どの案を採用しても、この計測の設計は同じです。

## 全案に共通する前提

### 範囲
ヒーローセクションから数節までです。各ファイル末尾に「ここまでが見本の範囲です」と
明示しています。店舗・投稿の詳細ページ、About、フッターは本開発フェーズの対象です。

### 写真
実素材が未確定のため、すべてプレースホルダ枠（グレージュの面）としています。
枠内に必要な縦横比と推奨解像度を表示し、HTMLコメントに `TODO 差し替え` を記載しています。
`design.md` が求める「写真主導」は、実写真の投入後に初めて成立します。
特に案B-2の投稿6枚の帯と案B-3のタイルは、実写真が入らないと評価できません。

### データ
掲載している店名・投稿はすべて `SAMPLE DATA` 表記のサンプルです。
`contents.md` の指示に従い、実在の店舗情報および実在URLは一切使用していません。
外部リンクはすべて `#` またはInstagramのアカウントURLです。
検索例の `Pierre Hermé` / `Paris` / `Tokyo` は、`contents.md` が指定した文字列です。

### 検索の仕様（第2回の3案）
店名・ブランド・国・都市・地方・種類・本文・英字表記のいずれかに一致します。
全角と半角、カタカナとひらがな、大文字と小文字、空白の有無は同じものとして扱います。
`Paris` と `パリ` はどちらでも同じ2件に到達します。

**プレースホルダの文言について。** `contents.md` が指定した
「ショコラティエ・ブランド・都市などで検索」は560px未満の画面では途中で切れるため、
狭い画面では「ブランド・都市で検索」に短縮しています。
`design.md` のモバイル優先の方針を優先した判断です。文言の可否をご確認ください。

### 技術
- 単体HTML／CSS／JavaScript。CSSフレームワークは未使用です。
- アニメーションは GSAP 3.12.5 + ScrollTrigger（cdnjs、バージョン固定）。
  `window.scroll` の監視はどの案でも使用していません。
- Webフォントは Google Fonts を `<link>` で読み込んでいます。
  本番（Next.js）では `next/font` によるセルフホストに切り替えます。
- `prefers-reduced-motion: reduce` では演出を停止し、完成した静止ページになります。
- GSAP本体とScrollTriggerのどちらかでも読み込めなかった場合、演出を行わず静止ページとして描画します。
  第2回の3案は、GSAPが無くても検索と絞り込みがそのまま動作します。
- さらに保険として、読み込みから3秒経っても隠れたままの要素は完成状態に戻します。

### 共通の意思決定
- 文字に `—`（emダッシュ）を使用していません。
- 「スクロール」を促す表示、装飾目的の番号ラベル、写真上に重ねるタグを使用していません。
- 角丸は案ごとに一つの基準に固定しています（第2回の3案は案Bと同じ12px）。
- 差し色は一色のみ（`#8A6A4F`）。全節で同一の色を使用します。
- 最小タップ領域 44×44px、コントラスト比 4.5:1 以上を確保しています。
- 件数の変化は `aria-live` で読み上げられます。

### 検証結果（第2回の3案）
Chromium（Playwright）で390px・1440pxの両方を実測しました。

- 横スクロール：両幅とも `scrollWidth == viewport`。発生なし
- JavaScriptエラー：0件
- 検索：`Paris` で16件→2件
- 絞り込み：国「日本」で6件、さらに都市「東京」で3件、解除で16件に復帰
- 0件になる選択肢が押せない状態になることを確認

## 本番スタック

デザイン確定後、Next.js（App Router）＋ shadcn/ui へ移植します。
現時点の単体HTMLは、移植時の視覚仕様書かつ挙動仕様書として扱います。
`contents.md` の Shop Data Model をそのままコンテンツ層のスキーマとし、
検索・絞り込み・詳細ページを本開発フェーズで構築します。
