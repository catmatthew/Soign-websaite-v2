## 2. 公開（URL の引き継ぎ）について

方針：現在の URL（`soigne-web.vercel.app`）を、新サイトでも使います。旧サイトのソースコードは保存します。

予定している手順（未実施）：

1. `soigne-web` の現在の状態に、保存用のタグとブランチを作る（公開サイトへの影響なし）。
2. 新サイトを、別ブランチで反映し、Vercel の確認用 URL で表示を確認する。
3. 公開日に、本番のブランチへ統合する。問題があれば、保存用のタグへ戻す。

公開前に決めること：

- 新サイトを `soigne-web` へ移すか、Vercel の接続先を `Soign-websaite-v2` へ切り替えるか（前者を推奨）。
- Vercel の「本番として扱うブランチ」（Vercel 管理画面の Settings → Git で確認）。
- `soigne-web` への書き込み権限を、Claude のセッションに付けるか（現在は読み取りのみ）。

## 3. 変更の進め方

### 依頼のしかた

- 変更したい箇所を、ページ名と、画面に出ている文言で指定してください（例：「法人向けページの『〇〇』を『△△』に変更」）。
- 文言は、指定どおりに反映します。指定のない箇所は変更しません。
- 関連する箇所に食い違いが出る場合は、変更せずに報告します（ご指示があれば直します）。
- 判断が分かれる点がある場合は、作業の前に確認します。

### Claude が毎回行うこと

1. 変更する。
2. 画面幅（1440／768／390／320px など）で、横のはみ出し・エラー・表示を確認する。
3. 変更履歴（`concept-b2-alternating.md`）に追記する。
4. 作業ブランチにコミットし、プッシュする。
5. 確認用プレビューを更新する。

### 公開後のルール（推奨）

- 本番のブランチへ直接反映しない。変更は別ブランチに反映し、Vercel の確認用 URL で確認してから、本番へ統合する。
- 理由：本番へ直接反映すると、誤りがそのまま公開されるため。

## 4. 写真・動画の入れ方

### 受け渡し

- 写真：チャットに添付してください。Claude が縮小して配置します。
- 動画：チャットでは受け取れない可能性が高いため、GitHub の Web 画面から、作業ブランチの `design-explorations/media/` へアップロードしてください（「Add file → Upload files」）。1ファイル100MBまで（GitHub の上限）。
- 元データ（縮小前の写真、書き出し前の動画）は、別の場所に保管してください。

### 写真・動画の枠

| 場所 | 種類 | 枠の比率 | 目安 |
|---|---|---|---|
| チーム（私たちについて） | 写真 | 4:5（縦長） | 長辺1000px以上。顔が枠の上寄りに入るもの |
| 商品（豆の各行） | 写真2枚（一枚目、ホバー・タップで二枚目） | 1:1 | 800px以上の正方形が望ましい。二枚目が無ければ一枚のみの表示にもできる |
| ヒーロー（B2-01） | 動画 | 16:9 | 音なし、約14秒のループ、H.264（mp4）で3MB以内。法人向けページの帯でも同じファイルを使う |
| 焙煎（B2-02） | 動画（配置済み：`media/video/roast-1280.mp4`） | 16:9 | 音なし、7秒のループ。H.264 1280×720、約3MB。画面に入っている間だけ再生。差し替える場合も同じ形式で |
| 量る手・袋詰め（B2-04） | 動画 | 1:1 | 音なし、短いループ。法人向けページで使用 |
| 注ぐ手（B2-03） | 動画 | 1:1 | 抽出の章（非表示中）で使用 |

- 写真のトーン（色味・白黒）を、チーム、商品それぞれで揃えると、見た目が整います。

## 5. 読みもの

- 構成は「最新の記事（1本、全文を折り畳みで表示）」と「過去の記事（一覧。行を押すとその場で全文が開く）」の2つです。
- 新しい記事を追加すると、現在の最新記事は過去の記事の一覧の先頭へ移ります（この入れ替えは Claude が行います）。
- 依頼の際は、カテゴリ、タイトル、署名、日付、本文をお渡しください。日付がない場合は、仮の日付を入れて報告します。
- 過去の記事が増えたら、記事ごとの独立ページ（例：`/journal/〇〇`）への切り替えを検討してください。

## 6. 変えてはいけない前提

### 表記

- 店名：Soigné Tokyo Coffee Roastery（ソワイエトウキョウコーヒーロースタリー）。
- 名前：山﨑 聖彦（「﨑」はたつさき）、石田 善大、髙岩 慧（「髙」ははしご高）。
- 肩書き：能力資料のとおり（CEO / 代表、Super Sales / 営業、Head Roaster＆QC / 焙煎士）。
- 「大切にしていること」（Tourné／n = 1／13°）は、能力資料の文言を、命令調のまま使う。
- 会社概要は載せない（法人化していないため）。お問い合わせの担当者名は載せない。

### 価格

- 個人向け（オンラインストア）は税込で表示する（総額表示義務）。
- 法人向け（卸価格）は税別で表示する。

### 表現の方針

- 健康・効能（「体に良い」など）、他社との比較、「日本一」「最高」などの最上級表現は書かない。
- 産地との取引は、基本的に商社経由のため、「農家に還元される」などと断定しない。
- 取引先の店名・人名は、掲載の許可を得たもののみ載せる。

### 書体と色

- 書体は3種類の役割で使い分ける：明朝（Shippori Mincho B1）は名前・見出しのみ、本文（Noto Serif JP）、小さなラベル（Zen Kaku Gothic New）。
- 色：勝色 `#181B39` と白 `#F8F9FA` が基本。

### Square

- Square のアクセストークンは、サーバー側のみに置く。ブラウザの JavaScript には絶対に入れない。権限は読み取りのみ。
- Claude は Square のカタログや在庫に書き込まない（「LP掲載」カテゴリの作成などは、お客様が Square の管理画面で行う）。

## 7. 公開前に残っている確認事項

### 文言

- [ ] 読みもの「Webサイト刷新のお知らせ」の日付（2026.10.23）は仮。読了時間と一覧の要約も仮。
- [ ] 読みものの署名の表記が揃っていない（「代表 山﨑 聖彦」と「山﨑 聖彦（Soigné 代表）」）。
- [ ] 法人向け「はじめかた」の「香りを試す5分から」は、実態と合っているか。
- [ ] 法人向け「取引の流れ」の「試飲までは無償で承ります。」と、冒頭の「サンプルと試飲は無料でお出ししています。」の表現を揃えるか。
- [ ] 法人向け「価格」の「同じ豆を店舗によって異なる価格でお出しすることはありません。」を残すか（対応するよくあるご質問は削除済み）。
- [ ] 法人向け「なぜ食後の一杯なのか」の注記（統計の出典）に、▲の印が残っている。
- [ ] トップの序の「奥ゆかしい」は、「奥深い」の意図か。
- [ ] フッターの「買う場所について」と、章の見出し「ご購入場所について」が食い違っている。
- [ ] 「私たちについて」の「目指していること」の三段は、新しく書いた文章。代表の最終確認が必要。

### 写真・動画

- [ ] チームの写真のトーンが揃っていない（山﨑のみ白黒）。代表の写真は 343×512px と小さい。
- [ ] アリーチャの二枚目（机の上の写真）は、ラベルの文字が崩れている（「Wothed」など）。カレンダーも「Jun 2025」。差し替えを推奨。
- [ ] デイリーパックの写真のラベルの一文の先頭に、余分な「一」がある。
- [ ] 商品の二枚目が仮の絵のまま（カンデリージャ、デイリーパック）。
- [ ] 動画（ヒーロー、量る手）は、仮の絵のまま。焙煎の動画は配置済み。

### 機能・外部サービス

- [ ] 豆の1・2行目（カンデリージャ、アリーチャ）の「オンラインストアで見る」は、商品ページではなくストアのトップへのリンク。
- [ ] フッターの「特定商取引法に基づく表記」「プライバシーポリシー」は、ページが未作成（リンク先は仮）。事業者名の表記も未定。
- [ ] Google フォームから、ドリップバッグの選択肢を外す（`docs/inquiry-form-design.md` の7章）。
- [ ] Square の接続（MCP）の再認可。週次の差分監視（Routine）に Square の接続を付ける操作は、claude.ai の Routines の画面で行う必要がある。

### 本番化の作業で行うこと（ご指示により、公開の作業と一緒に実施）

- [ ] 写真・アイコンの参照を、サイトの最上位からの指定（`/media/...`）に直す。試作は `media/...` の相対指定のため、`/about` や `/wholesale` のページで表示されなくなる。
- [ ] 商品情報（価格・商品名など）を、Square から自動で取得する仕組みにする。現在はページに直接書き込んでおり、`data/products.json` とも連動していない。Square の接続の再認可が前提。
- [ ] `favicon.ico` を、サイトの最上位（`/favicon.ico`）にも置く。
- [ ] ページの説明文（検索結果に出る文）と、SNS 共有時の画像・見出し（OGP）を用意する。
- [ ] 抽出の章を戻す場合は、保管中のコードに残っている開発用の説明文（「B2-03 · 注ぐ手 …」「B2-04 · 量る手 …」）を削除する。

### SEO（本番化の作業で行うこと）

- [ ] ページを本当の URL（`/`、`/wholesale`、`/about`）に分け、ページごとにタブ名・説明文（meta description）・見出しを持たせる。`#/…` の切り替えのままでは、法人向けページと私たちについてが、検索結果に単独で出ない。
- [ ] 説明文（全角80〜120字程度）の文案を用意し、確認を得る。
- [ ] 構造化データ（店名・読み・所在地・Instagram・ロゴ、記事の日付と著者）を入れる。「Soigne」（アクセントなし）でも見つかるようにする。
- [ ] 読みものの記事ごとのページ（`/journal/〇〇`）を作る。
- [ ] SNS 共有用の画像・見出し（OGP、1200×630px）を設定する。
- [ ] sitemap.xml と robots.txt を置く。Google Search Console への登録（お客様の作業）。

### SEO（公開前にお客様の判断が必要なこと）

- [ ] 独自ドメインを使うか。使う予定があるなら、新サイトの公開と同時の切り替えを推奨（後から移ると、検索評価の移し直しがもう一度必要になる）。
- 開幕の演出（約1〜3秒）は、表示速度の評価に影響し得るが、現状維持と決定済み（2026-10-23）。

### セキュリティ（本番化の作業で行うこと）

- [ ] Vercel の設定（`vercel.json`）で、セキュリティ用の応答ヘッダーを付ける：Content-Security-Policy（読み込み元を自サイトと Google Fonts に限定）、X-Content-Type-Options: nosniff、Referrer-Policy: strict-origin-when-cross-origin、frame-ancestors 'none'（他サイトへの埋め込み防止）、Permissions-Policy。
- [ ] Square のアクセストークンは、Vercel の環境変数に置き、サーバー側の処理からのみ使う。権限は読み取りのみ。リポジトリ・HTML・ブラウザ側には絶対に置かない。
- [ ] GSAP（`design-explorations/vendor/gsap/`）を更新するときは、npm の公式配布物から取り直す。

### セキュリティ（お客様の判断が必要なこと）

- [ ] 開発用リポジトリ `Soign-websaite-v2` は「公開（public）」設定。運用メモ、問い合わせフォームの設計、Square の商品ID、試作の文章などが、誰でも読める状態。非公開（private）への変更を推奨（GitHub のリポジトリの Settings → General → Danger Zone → Change visibility）。公開サイトの運用には影響しない。
- [ ] `.claude/skills/` に、外部の作者によるスキル（指示書）が多数含まれている。Claude のセッションが読み込む指示書のため、出所を確認できないものは削除を検討。

### 技術上の注意

- 複数の章を一度に飛び越えたとき（End キー、再読み込み、記事への直接リンクなど）、地色は約1.4秒後に正しい色へ戻る。その間は、前の地色のまま見える。
- 使われなくなった表示の記述（`.shelf` など）が CSS に残っている。見た目には影響しない。
